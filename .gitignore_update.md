# .gitignore Update - ChromaDB Files

## Changes Made

Added the following patterns to `.gitignore` to prevent committing large binary vector database files:

```gitignore
# ChromaDB vector database files
*.sqlite3
*.bin
backend/app/chatbot/db/
*.chroma
```

## Files Now Ignored

### Vector Database Directory
- `backend/app/chatbot/db/` - Entire ChromaDB directory
  - `chroma.sqlite3` - ChromaDB SQLite database (~400KB)
  - `*/data_level0.bin` - Vector embeddings data
  - `*/header.bin` - Index headers
  - `*/length.bin` - Vector lengths
  - `*/link_lists.bin` - HNSW graph links

## Why These Files Should Not Be Committed

1. **Large Binary Files**: Vector embeddings can grow to MB/GB sizes
2. **Environment-Specific**: Database paths and IDs are machine-specific
3. **Regeneratable**: The vector DB can be recreated from `transit_app_guide.txt`
4. **Frequent Changes**: Embeddings change with every reinitialization

## How to Recreate the Vector Database

If the vector database is missing, it will be automatically created on first run:

```python
# From backend/app/chatbot/chatbot.py
initialize_rag_system()  # Called automatically at startup
```

Or manually via API:
```bash
curl -X POST http://localhost:8000/api/v1/chatbot/reinitialize
```
